Tabish Ali Mughal's personal portfolio (home page + resume), which is also the **developer website
for the Entity apps & games** on Google Play: one page and one privacy policy per game, the AdMob
`app-ads.txt`, and the force-update manifest the games read.

**Live:** https://tabishalimughal.github.io

Static HTML/CSS/JS, no build step. Repo: `TabishAliMughal/TabishAliMughal.github.io`, branch `main`.

## Important rules

- **`app-ads.txt` must stay at the repo root** and contain exactly:
  ```
  google.com, pub-9644064778878685, DIRECT, f08c47fec0942fa0
  ```
  AdMob looks for it at `<website>/app-ads.txt`; the Play listing "Website" field must be exactly
  `https://tabishalimughal.github.io`.
- **Do not move `entity/games/manifest.json`.** Every game's force-update check (`useForceUpdate`)
  reads `https://tabishalimughal.github.io/entity/games/manifest.json`. It is the only copy.
  Format, keyed by Android package:
  ```json
  { "com.entity.sudoku.game": { "latestVersionCode": 1, "minSupportedVersionCode": 1 } }
  ```
  After publishing a release: set that package's `latestVersionCode` to the new versionCode, set
  `minSupportedVersionCode = latestVersionCode - 2` (minimum 1) or higher to force an immediate
  update, then commit and push. Games cache the result for 6 hours but re-check on cold start.
- **Do not rename the repo.** `<user>.github.io` is what makes the site serve at the root URL; the
  app-ads.txt, manifest and Play Console privacy policy URLs all depend on it.
- Do not delete the `privacy/<slug>/` redirect stubs.

## Adding a Play Store link (one line)

When a game is live, paste its listing URL as that slug's `playUrl` in `assets/js/apps-data.js`:

```js
"entity-sudoku": {
    playUrl: "https://play.google.com/store/apps/details?id=com.entity.sudoku.game",
    testingUrl: "https://play.google.com/apps/testing/com.entity.sudoku.game"
},
```

Commit and push. The badge becomes "Get it on Google Play" on both the home card and the game page.

## Closed testing (beta) links

`testingUrl` is the Play closed-testing opt-in page, `https://play.google.com/apps/testing/<package>`. It
drives the blue "Join the beta (Android)" button on the home card and the game page, the game page's "How
to join the beta" link (to `/#beta-test`), and the game's row in the home "Help test Entity games" block
(`#beta-test`, under the Apps & Games grid: 4 steps + "access is by invitation - email your Play Gmail").
The same URL is hard-coded in the HTML as the no-JS fallback, so keep both in sync. When testing ends,
set `testingUrl: ""`: `apps.js` removes that game's beta button, link and row (and hides `#beta-test`
once no row is left). Testers must be on the closed-testing tester list in Play Console, otherwise the
opt-in page says they are not a tester.

The **Google Play developer page** (`https://play.google.com/store/apps/dev?id=8198153788316941090`) is `window.ENTITY_PLAY_DEVELOPER_URL` in the same
file. Every link to it has class `play-dev-link` and the URL also written in its `href` (no-JS fallback,
and the résumé, which loads no JS); `apps.js` overwrites the href from `apps-data.js`. If the URL ever
changes, update `apps-data.js` and `grep -r play-dev-link` for the hard-coded fallbacks.

## Adding a VS Code extension (one entry)

Add one object to `window.VSCODE_EXTENSIONS` in `assets/js/extensions-data.js` (facts only, from the
extension's Marketplace page / README):

```js
{
    id: "TabishAliMughal.<Name>",            // Marketplace itemName; card anchor = #ext-<id, lower-cased>
    name: "Entity <Name>",
    description: "One line.",
    features: ["3-5 short", "key features"],
    icon: "assets/images/extensions/<name>.svg",
    marketplace: "https://marketplace.visualstudio.com/items?itemName=TabishAliMughal.<Name>",
    source: ""                               // public repo URL, or "" if the repo is private (no Source button)
},
```

Put the icon in `assets/images/extensions/` (the extension's own icon, square, SVG or 256 px WebP).
`assets/js/extensions.js` renders the card (Install + optional Source buttons, `target="_blank" rel="noopener"`).
Check at 360 px and 1280 px, commit and push. The "View all on VS Code Marketplace" button uses
`window.VSCODE_PUBLISHER_URL` in the same file.

## Cost calculator (`/cost-calculator/`)

Clients estimate a project themselves: pick a project type or features, a deadline, optional AI-assisted
development and a support option; the itemised estimate updates live in USD or PKR. In USD a note explains
that USD prices are higher because of the time-zone difference (work is done outside regular local hours).
"Contact me with this estimate" opens the visitor's email app (`mailto:`) with the summary; nothing is sent
or stored by the page. Linked from the nav ("Pricing"), the Contact section call-to-action and the footer.

The form has a currency bar and six numbered sections: 1 Project type, 2 Core features, 3 Add-ons and
extras, 4 Delivery options (documentation, AI-assisted, deadline/rush), 5 Support, 6 Your estimate. A
service goes in Core or Add-ons by its `category` (`core` | `addon`) in the private tool's
`data/services.php`; change it there and re-export, never here. The summary splits the total into Core,
Add-ons, Delivery options and Support (one-time) subtotals; the split is display-only (same totals as
`cost-model.js`).

**Prices are never edited here.** `cost-calculator/pricing-data.js` is generated from the private tool
`D:\persional\Entity\Finance\Entity-CostCalculator_finance` (its `data/*.php` are the single source of truth):

```
cd D:\persional\Entity\Finance\Entity-CostCalculator_finance
php tools/export_portfolio_pricing.php
```

Then bump `pricing-data.js?v=` in `cost-calculator/index.html`, commit and push. The export is a whitelist
(no discounts, internal conversion rate, client data or saved quotes) - field mapping and the PHP parity
check are in that project's `docs/portfolio-export.md`. `cost-model.js` mirrors its `lib/Calculator.php`; if
the PHP formula changes, change both.

## Screenshots and YouTube video

Each game page has two generated blocks, between `<!-- screenshots:start -->` /
`<!-- screenshots:end -->` and `<!-- video:start -->` / `<!-- video:end -->`. Never edit inside the
markers by hand - run the script:

```
python tools/sync_screenshots.py            # add --force to re-encode every WebP
```

- **Screenshots:** the script reads `D:\persional\Entity\docs\games\<slug>\screenshots\*.png`
  (1080x1920 store shots, sorted by file name), writes `<name>-540.webp` + `<name>-1080.webp` to
  `entity/games/<slug>/screenshots/` (quality 80, lowered until < 120 KB), deletes WebPs whose PNG
  is gone, and renders a sideways-scrolling row of phone frames (lazy-loaded, `srcset`, alt text
  from the file name: `03-gameplay.png` -> "Bubble Shooter – gameplay", `-dark` -> "(dark theme)").
  No PNGs -> the block stays a hidden, empty card. Name the PNGs `NN-what-it-shows.png`.
- **YouTube video (one line per game):** put the video ID or URL for that slug in
  `tools/game_videos.json`, e.g.
  ```json
  "entity-bubbleshooter": "https://www.youtube.com/watch?v=VIDEO_ID",
  ```
  then run the script. It renders a lazy, 16:9 `youtube-nocookie.com` embed (watch, `youtu.be`,
  `shorts` and `embed` URLs or a bare 11-character ID all work). Empty string -> no video block.
  A malformed entry stops the script before any page is changed.

Commit the page(s) and the `screenshots/` folder, then push.

## Adding a game page

1. Copy `entity/games/entity-arrows/` (both `index.html` and `privacy/index.html`) to
   `entity/games/<slug>/` and replace name, slug, package, tagline and texts (facts only from that
   game's README/docs). Keep `data-app="<slug>"` and the `.app-store-badge` in the hero card.
2. Keep the shared head block (`/assets/css/tokens.css`, `/assets/css/entity.css`); no inline styles.
3. Add the game to `LOGOS` in `tools/normalize_app_logos.py` and run `python tools/normalize_app_logos.py`
   (writes `assets/images/apps/<slug>.webp`; never hand-export logos).
4. Add an `<article class="app-card" id="app-<slug>" data-app="<slug>">` to `#apps` in `index.html`,
   `"<slug>": { playUrl: "", testingUrl: "" }` to `assets/js/apps-data.js`, the policy to `privacy/index.html`, and the package to
   `entity/games/manifest.json`.
5. Check at 360 px and 1280 px: no horizontal scroll, no broken images.

## Deployment

Push to `main`. `.github/workflows/pages.yml` copies the repo root (minus `.git`, `.github` and
`assets/scripts`) into `_site` and deploys it with GitHub Actions Pages (Settings > Pages > Source =
GitHub Actions). Live in about a minute.

## Design system

Dark only, one set of tokens for every page, echoing the Entity game logos: deep navy `#0A1528`, a
faint circuit-board grid, and a blue (`#5BB8FF`) -> amber (`#FFB648`) gradient for display text.
Fonts: Unbounded (display headings) and IBM Plex Sans (everything else). All text pairs >= 4.5:1
contrast; amber focus ring; `prefers-reduced-motion` respected. Full token table, page blocks and
the detailed game-page steps: [docs/DESIGN.md](./docs/DESIGN.md).
